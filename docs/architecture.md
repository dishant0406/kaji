# Architecture

Kaji is a macOS-only SwiftUI app. It embeds libtermy through the local `TermyKit` C module and keeps all app behavior inside the `Kaji/` executable target.

## Repo Shape

```text
Kaji/                       App target
KajiHookClient/             Native provider hook helper
KajiParentAgentRuntime/      TypeScript Parent Agent runtime using Pi packages
TermyKit/                    C module exposing termy.h and libtermy_ffi.dylib
Tests/KajiTests/            Swift Testing suite
docs/                        Project docs
scripts/                     Setup, checks, packaging
```

There is no iOS companion target, no shared protocol package, and no remote server layer.
`Kaji/Resources/HugeIcons/` carries the bundled Hugeicons free stroke-rounded font and CSS map used by the app icon wrapper. `Kaji/Resources/FileIcons/MaterialIconTheme/` carries the pinned Material Icon Theme manifest, SVG assets, license, and version metadata used by the project file tree. `Kaji/Resources/Fonts/Terminal/` carries the bundled JetBrainsMono Nerd Font Mono family used as the default terminal font so Powerline and Nerd Font prompt glyphs render without requiring a system font install.
The optional AI Gateway installs Claude Code Router externally into Application Support on demand; Kaji does not bundle or maintain its own gateway binary.

## Core Runtime

- `Kaji/KajiApp.swift` wires the app scene graph, stores, in-app settings modal flow, and app delegate lifecycle. The main scene advertises that it accepts external events so `kaji://` CLI project commands route into an existing window before `KajiURLCommandHandler` selects or adds the project.
- `KajiHookClient/` is a native Swift executable bundled beside the app binary. Provider hooks call it directly, and it posts normalized provider events to Kaji through macOS `DistributedNotificationCenter`.
- `Kaji/Services/AppEnvironment.swift` builds the concrete dependencies used by the app state.
- `Kaji/Models/AppState.swift` owns project selection, worktree selection, workspace tabs, split trees, and workspace persistence. Project selection is separate from workspace creation, so a selected project can render an empty state until the first tab is opened.
- `Kaji/Models/WorkspaceReducer.swift` is the state transition layer for workspace tabs, panes, splits, and focus.
- `Kaji/Services/Termy/TermyService.swift` owns Kaji-managed Termy config, render defaults, and theme color publication.
- `Kaji/Views/Terminal/Termy/TermyTerminalNSView.swift` is the AppKit bridge that creates and drives each `TermyFfiTerminal`, including resize, frame snapshots, input forwarding, event draining, and hidden-pane visibility.
- `Kaji/Views/Terminal/TerminalViewRegistry.swift` keeps terminal views alive across SwiftUI updates.

## Workspace Model

```text
Project -> Worktree -> WorktreeWorkspace -> WorkspaceTab -> SplitNode -> TabArea -> TerminalTab
```

- A `Project` is a top-level folder the user adds to Kaji.
- A `Worktree` is either the primary project checkout, a Rift workspace created by Kaji, or an external Rift workspace discovered for that project.
- `WorktreeWorkspace` owns the ordered top-level tabs for a worktree and remembers which workspace tab is active.
- `WorkspaceTab` is the user-facing tab in the title bar. It owns one full-canvas split tree plus the focused pane inside that tree.
- `SplitNode` stores the pane tree inside one workspace tab. `SplitContainer` renders each branch through the local `Bonsplit` package, which wraps native `NSSplitView` resizing while Kaji remains the source of truth for pane identity, focus, tabs, and persistence.
- `TabArea` remains the leaf model used by the split tree, but after the tab rewrite it acts as a pane container for one active content stack rather than as the app's primary tab concept. Inactive terminal, browser, and parent-agent panes stay mounted for live session continuity. Each pane owns one stable Monaco host for all editor tabs in that pane; switching files rebinds the existing web view to the next editor state and swaps Monaco models instead of rebuilding WebKit. Older clean editor backing stores can still be released by budget policy, while preview, diff, VCS, and problems panes unmount their SwiftUI/AppKit content when inactive.
- `TerminalTab` is the content model hosted by a leaf pane and can represent a terminal, editor, VCS view, or diff viewer.
- `TabDragCoordinator` serves pane-local tab drag targets. `PaneReorderCoordinator` serves full-pane drag targets from the pane header: center drops swap two panes, while edge drops move the source pane into a new split beside the target pane.

Workspace state is persisted per worktree so every project can keep separate workspace tabs, split layouts, focus state, terminal sessions, editor tabs, and VCS layouts across launches. A project can also remain selected with no workspace root when its tabs are closed or before any tab has been opened.

## Major Subsystems

- Terminal: `TermyTerminalNSView`, `TerminalPane`, `TerminalSearchBar`, `TerminalSettingsStore`, and `TermyService`. `TerminalPane` keeps terminal views mounted for session continuity while propagating SwiftUI visibility into the AppKit bridge, and the bridge starts the user's shell through libtermy, forwards encoded keyboard and mouse input, snapshots the terminal grid, drains title/process events, closes the owning tab on Termy process exit, supports bracketed paste, clears scrollback, delivers footer-injected commands exactly once through `TerminalInjectedCommandDelivery`, and reports search counts from libtermy search batches. App-level copy and paste commands route to the terminal that owns the key window's first responder before falling back to the model-focused pane, while native text responders still keep standard edit behavior. Terminal suspension is owned by `TermyTerminalNSView.setSurfaceVisible` rather than SwiftUI surface disappearance so root-view updates cannot pause a visible pane. TermySwiftEmbed keeps PTY wakeup handling isolated from SwiftUI, clamps active and inactive scrollback from runtime config before output can accumulate, allows active-cadence wakeups only while input echo is pending, and suspended wakeups always drain buffered PTY events so output never waits for a later keypress. `TerminalBundledFont` registers the bundled JetBrainsMono Nerd Font Mono family at launch, and `TerminalSettingsFontMigration` moves legacy `SF Mono` defaults to that bundled prompt-glyph-capable font while preserving later user font choices. `TermyTypographyDefaults` and `TermyTerminalConfigDefaults` write Kaji-managed font, cursor, padding, truecolor, shell integration, scrollback, inactive scrollback, copy, and glass keys into the generated Termy config while preserving user-authored lines. `TermyConfigDiagnostics` validates the merged config through libtermy and exposes parse issues in Terminal Settings before users reload terminal surfaces.
- Editor: `EditorTabState`, `MonacoEditorView`, `MonacoPreloadService`, `MonacoAssetServer`, `TextBackingStore`, and the bundled Monaco runtime under `Kaji/Resources/MonacoEditor`. The file editor is Monaco running inside a hardened `WKWebView` loaded from a loopback-only static asset server that serves only bundled Monaco files. Monaco uses a shared WebKit configuration, a non-persistent data store, a preloaded warm web view for the first pane editor host, and one reusable editor host per `TabArea` so first open and file tab switching avoid unnecessary white reload flashes. Monaco keeps per-model view state inside the runtime, rebinds bridge messages when the pane host moves between editor tabs, and owns editor language behavior, including highlighting, folding, quick outline, and marker production. `TextBackingStore` remains the Swift-side mirror with cached full-text and UTF-16 length metadata so save, search state, markdown preview sync, inline edits, line navigation, and agent tools can use synchronous Swift models. Monaco sends diagnostics back through the bridge to `DiagnosticsStore`; Kaji no longer runs editor language servers or Swift-native syntax, Tree-sitter, folding, symbol, viewport, or language-pack infrastructure for the file editor. KajiKit script editing uses SwiftUI text controls rather than the removed native editor stack.
- Git and VCS: `GitRepositoryService`, `RiftWorkspaceService`, `VCSTabState`, and the attached source-control panel under `Kaji/Views/VCS/`. Diff loading keeps git semantics in `GitRepositoryService`, parses patches directly into flat `DiffDisplayRow` values with optional inline change segments, and renders diff content through viewport-bounded AppKit drawing so large hunks avoid full-file `NSTextView` layout work while preserving the SwiftUI file headers, gutters, comments, split/unified modes, and context expansion controls. Pull request state is branch-scoped in `VCSTabState`, preserves the just-created PR as authoritative through the post-create refresh, broadcasts create/merge/close events across all VCS panes for the same worktree, and keeps negative GitHub lookups on a short TTL so the attached sidebar does not stay stuck on stale "Create PR" state.
- Projects and worktrees: `ProjectStore`, `WorktreeStore`, `ProjectOpenService`, `ProjectSelectionService`, `KajiURLCommandHandler`, and `WorktreeSetupRunner`. `ProjectSelectionService` is the shared add-or-select path for the open-folder panel, Ask project actions, and the `kaji://open-project/<base64url-path>` URL command used by the optional shell command.
- Workspace navigation: `FileSearchService`, `PaletteOverlay`, `QuickOpenOverlay`, `AskOverlay`, `WorktreeSwitcherOverlay`, `ExternalIDECatalog`, `ExternalIDESettings`, and `ExternalIDEOpenService` handle indexed quick-open, cross-project prompt dispatch, saved script execution, worktree switching, and opening the active worktree in the user's selected external app from the top bar, including Finder through a native Finder open path. `ShortcutReferenceCatalog`, `KeyBindingStore`, and `ShortcutActionDispatcher` form the shared command layer: actions can be key-bound or command-palette-only, terminal host shortcuts resolve through the same configurable bindings as the rest of the main window, and workspace tabs, pane focus, split resizing, side panels, and modal dismissal remain reachable without pointer input. `ModifierKeyMonitor` and the attached shortcut hint view modifier provide modifier-hold keycap overlays directly on visible controls, including workspace tabs, sidebar projects, top-bar actions, footer controls, browser toolbar actions, and modal search fields. Search in Files uses the FFF index on a dedicated background queue, bounds interactive grep work, truncates preview lines before SwiftUI layout, and renders flattened lazy result rows so common queries do not realize whole file groups while scrolling. `AskOverlay` reuses the command-palette shell, supports slash commands, file mentions, attachments, task recipes, KajiKit scripts, native Git commands, and inline routing annotations such as `:p:`, `:wt:`, `:t:`, `:m:`, `:h:`, `:s:`, `:task:`, `:pa:`, and `:x:` inside the query field for hands-free targeting. `:git`, `:branch`, `:switch`, and `:checkout` run or select Git operations in the active worktree while streaming output inside the same native command panel instead of opening a terminal tab. `AskCommandDispatcher` routes prompt text into existing terminal sessions when possible and falls back to opening a new provider session before sending. KajiKit scripts are managed by `KajiKitScriptStore`, stored in `~/.kajikit/scripts.json`, resolved by global/project scope, planned into temporary run scripts under `~/.kajikit/runs/`, and streamed inside the command palette by `KajiKitScriptRunner` instead of taking over a workspace pane.
- Native file search isolation: `FFFSearchService`, `FFFSearchIndexStore`, and `FFFWorkerClient` communicate with the persistent `KajiFFFWorker` helper through bounded typed JSONL frames. Only the helper target links `FFFKit` and loads the integrity-pinned FFF 0.10 dylib, so a native scanner fault terminates the restartable worker rather than Kaji. Worker requests are serialized with timeouts and bounded restart backoff; project removal closes worker indexes before mutating visible state.
- Project removal: `ProjectRemovalService` owns an idempotent, main-actor transaction shared by manual removal and already-emptied workspace finalization. It persists a removal tombstone before stopping project-scoped agents, terminals, notifications, and search indexes; then removes workspace, project, and worktree state, selects a deterministic replacement, performs bounded disk cleanup, and clears the tombstone. Startup replays incomplete tombstones, and duplicate removal requests are coalesced. If persistence or disk cleanup fails, the tombstone is kept (a manual attempt keeps `retryCount` unchanged, a startup recovery attempt increments it) and recovery becomes non-fatal; after `ProjectRemovalService.maxRetryCount` consecutive recovery failures the tombstone file is quarantined with a `.stale-<yyyyMMdd-HHmmss>` suffix so a permanently failing cleanup can never trap app launch. Bundled CLI binaries such as the Rift binary are always resolved through `Bundle.appResources` (never `Bundle.module`), whose candidate list includes the installed `Contents/Resources/Kaji_Kaji.bundle` layout, so removal-time Rift cleanup cannot crash on a missing SPM resource-bundle path.
- File tree icons: `FileIconManifest`, `FileIconResolver`, `FileIconImageCache`, and `FileTypeIconView` keep file-type icon lookup in the presentation layer. `FileTreeService` still emits only filesystem entries, while the resolver maps bundled Material Icon Theme SVGs by exact relative path, exact file name, longest compound extension, folder path, expanded-folder state, and safe default fallbacks without reading user-controlled icon paths.
- Speech to text: `SpeechInputController`, `SpeechHotkeyMonitor`, `SpeechAudioCapture`, `SpeechTranscriber`, `SpeechModelRegistryStore`, and `SpeechInsertionRouter` provide local hold-to-dictate input through FluidAudio. The controller is started from the app lifecycle, exposes the Settings tab state, and refuses enablement unless the selected model is cached. The hotkey path uses local and global AppKit monitors plus physical key polling and a release safety poller so release loss cannot leave audio capture running. `SpeechAudioCapture` streams the microphone through an `AVAudioEngine` realtime tap whose callback is installed as a nonisolated `@convention(block)` handler so it never touches an actor-isolated context on the audio thread; buffers accumulate in the lock-protected `SpeechAudioChunkAccumulator`. A chunk loop snapshots the accumulator periodically and `SpeechTranscriptQueue` serializes transcription plus insertion, branching on the selected model's mode: release-transcription models transcribe each chunk directly with no session lifecycle, while live-streaming EOU models hold one session per capture, deliver only new token deltas relative to the last partial, and flush the remaining delta on stop; in both modes text accumulates when no insertion target is available and flushes to the clipboard on stop. Models load once per runtime and unload after capture unless keep-warm is enabled. Speech models are defined by the editable `speech-models.json` registry, downloaded from the trusted HTTPS Hugging Face origin into Application Support with byte-level progress, loaded on demand by FluidAudio ASR managers, optionally kept warm, and unloaded after use when the setting is disabled. Registry validation rejects untrusted origins and unsafe repository or revision paths, and Hugging Face credentials are attached only to the exact trusted origin. Insertion routes into Termy terminals, native text views, Monaco editor state, focused WebKit text fields, or the active editor provider without adding speech-specific logic to those surfaces.
- Meeting audio: `ScreenCaptureMeetingAudioCapture`, `MeetingAudioEventQueue`, `MeetingAudioProcessingPipeline`, `MeetingAudioChunker`, `MeetingRealtimeAudioPacketizer`, and `MeetingTranscriptionRuntimeRouter` form the native meeting transcription input layer. ScreenCaptureKit emits system and microphone audio on separate serial queues without registering a video output. Callbacks copy sample buffers into owned values, a bounded actor queue reports backpressure gaps explicitly, and AVAudioConverter normalizes each source to 16 kHz mono float audio. Local and cloud batch routes use bounded 20-second chunks, while realtime routes produce 100 ms PCM16 packets with canonical 16 kHz ranges. OpenAI realtime applies deterministic 16 kHz to 24 kHz PCM16 conversion at its provider boundary. Independent per-track router workers own all provider awaits, bounded packet queues, 30-second replay rings, session rotation/reconnect plans, and transcript revision reduction. `FluidAudioMeetingTranscriptionProvider` is the only Meeting Notes provider that adapts normalized samples into SpeechInput values.
- Meeting transcription integration: `MeetingTranscriptionProviderModule`, `MeetingTranscriptionProviderCatalog`, `MeetingTranscriptionEndpointStore`, `MeetingTranscriptionModelCatalogStore`, and `DefaultMeetingRecordingRuntimeFactory` isolate provider wire protocols, endpoint destinations, account-scoped model discovery, credential binding, route validation, and runtime construction from the coordinator and UI. Provider modules contain protocol behavior but no cloud model identifiers. OpenAI, Deepgram, and ElevenLabs load models from their authenticated model-list APIs; AssemblyAI and endpoints without compatible discovery accept an explicit opaque model or deployment identifier; FluidAudio continues to use the editable local speech registry. Endpoint profiles select built-in or user-defined HTTPS/WSS bases, protocol variant, discovery method, and region. Credentials are bound to the endpoint profile and an exact SHA-256 origin fingerprint, so a key configured for an official provider host is never reused for a custom destination. Custom profiles allow public TLS endpoints only, reject user-info, query-bearing bases, private, loopback, link-local, metadata, and ambiguous hosts, validate DNS results before use, deny redirects, and retain existing response, frame, event, and byte bounds.
- Meeting transcription settings: `MeetingTranscriptionSettingsController` derives one progressive configuration path from the selected provider, endpoint, endpoint-bound credential, mode, and model catalog. Built-in endpoints show a selector with an explicit Add action; custom endpoint and API-key forms mount only while creating or editing. Discovery-backed models remain hidden until a credential exists, refresh automatically after credential selection, and use the searchable model picker without a second search field. Manual model entry is the primary control only for manual-discovery endpoints and an explicit fallback for custom endpoints. Fixed mode and retention values render as text or remain hidden, while keyterms, automatic language detection, and local fallback stay under the collapsed advanced section.
- Meeting notes: `MeetingNotesCoordinator`, `MeetingContentSharingPicker`, `MeetingSessionStore`, `MeetingProjectContextProvider`, `KajiMeetingNotesAgentClient`, and the views under `Kaji/Views/MeetingNotes/` provide app-level meeting capture, live transcript, progressive notes, and history. Recording starts only after a short-lived consent snapshot freezes the exact model ID, protocol operation, endpoint profile and origin, raw-audio destination, source tracks, endpoint-bound credential reference, retention claim and attestations, diarization, local fallback choice, local retention, and project metadata categories. Editing or deleting an endpoint profile cannot redirect an active meeting. Custom destinations are disclosed by hostname and never inherit hosted-provider retention or regional claims. Consent expiry, configuration identity, disclosures, and attestations are checked before the picker, immediately after it, and immediately before capture. Provider status is presented as locally configured until a real request verifies connectivity and entitlement.
- Meeting content picker callbacks enter through a generation-scoped nonisolated Objective-C observer proxy and transfer immutable callback payloads to `MainActor` before accessing picker state. Cancellation, stale generations, repeated callbacks, callbacks after stop, and deallocation complete at most one continuation and cannot trigger macOS 26 executor preconditions.
- Meeting runtime recovery: Each transcription track uses a mode-derived nonblocking queue, a 30-second PCM replay ring, bounded jittered retries with provider retry-after support, and generation plus provider-epoch validation. Disconnects, rate limits, provider rotation warnings, and scheduled duration limits replace the failed provider session, replay retained packets into the new epoch, and enforce a canonical final-result cutover. Cloud routes never fall through to another cloud provider. A frozen consent snapshot must both enable local fallback and contain an explicit local route before the catalog resolves FluidAudio; otherwise exhausted ranges become sanitized persisted gaps while capture continues. Drain timeout cancellation awaits pipeline, router, worker, and provider completion before finalization. Per-track reconnect, rate-limit, fallback, failure, and completion health is persisted without provider response bodies.
- Meeting note revisions: The synthesis state persists pending and synthesized segment IDs, lifecycle status, attempt count, last attempt, next retry, and a stable sanitized failure code. Final transcripts add IDs only when a notes model exists, speaker metadata amendments requeue affected IDs, and the strict cross-runtime payload includes speaker labels plus source kind and source label. The headless Kaji runtime validates the exact frozen provider/model and credential without inference before reporting readiness. Transient provider, timeout, invalid-response, and cancellation failures use persisted exponential retries capped at five minutes; contract, model, and credential failures pause until manual retry. Startup reschedules retryable terminal meetings, stop performs one final attempt, and manual retry works for active or completed meetings without allowing stale responses to overwrite user edits. Sessions without a notes model clear pending state. Notes and pin mutations carry the target session ID so an active recording can remain displayed while an unrelated history selection is preserved.
- Guided commits: `:commit` is a native `AskOverlay` flow. Kaji loads the full selected-file inventory, creates an immediate native draft from complete metadata, optionally refines wording through a short-lived headless Kaji runtime RPC command backed by the same oh-my-pi model catalog and custom providers as Runtime Models settings, and keeps staging plus `git commit` execution inside `GitRepositoryService`. Commit-message settings choose the refinement provider/model from the live runtime model list, fast/medium/detailed output context, and persisted user wording instructions that are injected into the refinement prompt without overriding the inventory or no-tool constraints.
- Parent-agent runtime: `ParentAgentTaskStore`, `ParentAgentController`, and `ParentAgentProcess` remain as graph-agent orchestration infrastructure over the Kaji-owned TypeScript runtime in `KajiParentAgentRuntime`, which imports Pi through pinned npm packages instead of vendoring the Pi repository. Kaji launches the bundled or source runtime entrypoint as a child process and exchanges newline-delimited JSON over stdin/stdout; there is no socket server. The controller is split by tool family so workspace tools, child-agent tools, provider choice tools, observation tools, review tools, parsing, and formatting stay separate. Parent tasks persist in `parent-agent-tasks.json`; interrupted in-flight tasks restore as stale. The old parent-agent SwiftUI home and parent-agent timeline views are removed.
- Browser: `BrowserPaneState`, `BrowserPageState`, `BrowserPane`, `NativeBrowserSurface`, `BrowserWebController`, and the WebKit files under `Kaji/Views/Browser/WebKit/` add an embedded in-Kaji browser split backed by native `WKWebView`. Kaji uses WebKit's persistent `WKWebsiteDataStore` for cookies, login state, localStorage, and sessionStorage; handles navigation, downloads, file uploads, JavaScript dialogs, OAuth popups, screenshots, page text, JavaScript eval, Playwright-compatible ref snapshots/interactions, console capture, WebKit-observed network capture, and WebContent process recovery in Swift/AppKit. `KajiBrowserControlBroker` publishes a session-scoped localhost broker and writes its current session to `~/.kaji/browser/session.json`. The bundled `kaji-browser-mcp` server is installed explicitly from Settings into normal user MCP config files, starts without session-specific shim injection, checks broker reachability through `kaji_browser_accessible`, and always exposes WebKit-native `kaji_browser_*` tools plus Playwright-compatible `browser_*` aliases with structured recovery errors when Kaji Browser is unavailable. Kaji no longer bundles Chromium, CEF, CDP, Playwright, or Chrome DevTools MCP for the embedded browser. Workspace snapshots persist open browser pages and the selected browser page per pane.
- Kaset Music: `KasetMusicPanel` embeds the `KasetEmbedded` SwiftPM product from the Kaji-maintained Kaset fork. Kaji owns only the settings flag, sidebar footer entry point, side-panel sizing, and panel lifecycle; YouTube Music auth, library/search/queue UI, and WebKit-backed DRM playback stay inside the Kaset package so Kaji does not copy or fork Kaset source into its own app target. `MainWindow` owns one persistent `KasetEmbeddedController`, keeps `KasetEmbeddedPlaybackHost` mounted as a hidden 1x1 host while the panel is closed, and passes the same controller to the centered `KasetNowPlayingFooterControl` in the workspace footer. Closing the panel therefore removes the heavy Kaset UI but preserves playback state; the footer control can play/pause, seek, skip previous/next, open a queue popover backed by package queue snapshots, play a queue item directly, and quit the embedded player by clearing playback, queue, pending video, and WebViews through `stopPlayback`. Disabling the feature sends `shutdownKasetMusic` so the package can tear down playback and monitoring explicitly. This surface is app-level rather than project/worktree-scoped and is not registered with Kaji Browser MCP or `KajiBrowserControlRegistry`.
- Coding agents: `Kaji/Services/CodingAgents/` is the extension point for terminal-native coding agents. Each agent folder exports a `CodingAgentModule` with identity, aliases, icon, executable names and search paths, config/data directories, default command, install command, prompt/model/resume command builders, skill invocation style, stop automation, model strategy, usage strategy, history strategy, instruction files, skill roots, and hook installation. `AskProvider` is now a registry-backed value type rather than the source of truth, so adding an agent should require adding a module and registering it in `CodingAgentRegistry` instead of editing palette, settings, parent-agent, command, and Mission Control switches.
- AI Gateway: `Kaji/Services/AIGateway/` manages optional local routing for Claude Code, Codex, and compatible clients through Claude Code Router only. Kaji installs the external `@musistudio/claude-code-router` npm package on demand into Application Support with a managed Node runtime and install manifest, defaults to port 5254, clears stale listeners before launch, reserves the next local core port plus a local management port, and runs with `CCR_INTERNAL_*` directories so it never touches a user's global CCR state. Kaji persists gateway settings in Application Support, stores the gateway token and provider API keys in `ai-gateway-secrets.json` with 0600 file permissions, writes generated Claude Code Router config, starts/stops the child process without a shell, checks `/health`, redacts logs, and exposes copyable connection instructions. Claude Code Router config is generated with proxy mode, system proxy, network capture, observability, and ToolHub disabled by default so the process remains idle until model requests arrive. Azure OpenAI routes are emitted as v1 Responses providers with environment-backed upstream auth, so GPT-5-class Azure deployments use Responses-compatible paths rather than legacy chat completions. The settings UI is setup-first: common provider, model, API key, client configuration, and start/restart actions stay visible while port, token, fallback routes, raw provider rows, manual shell commands, and logs live behind advanced disclosure. Kaji injects only the local gateway token and base URLs into Kaji-launched terminal shells when the gateway is enabled; provider API keys are passed only to the gateway process environment. Claude Code and Codex configuration helpers merge gateway model/provider entries into their user config files without touching unrelated hooks or MCP settings.
- Coding-agent executable discovery and setup: Kaji resolves external coding-agent CLIs through the user's configured command or shell lookup, and only uses explicit Kaji-managed directories for Kaji-owned runtimes. It does not guess Homebrew, npm, nvm, or per-agent install directories during launcher availability checks. KajiCode smoke tests, hook installation, and MCP registration use the shell-derived execution environment so script-based CLIs that depend on `/usr/bin/env` can find their runtime without hardcoded paths; MCP config writes only the resolved `PATH`, not the full shell environment. Launcher enable/disable and provider hook refresh run provider sync work off the main actor.
- Notifications and activity: `NotificationStore`, `NotificationNavigator`, `ProviderEventReceiver`, `ProviderEventDispatcher`, `NotificationIntegrationStore`, `NotificationEndpointSender`, `NotificationRouteSoundResolver`, `NotificationDisplayTextResolver`, `CodexSessionMonitor`, `CodexOutboundNotificationCoordinator`, `AgentProviderCatalog`, `AIActivityStore`, `AIActivitySocketRouter`, `KajiAgentActivityBridge`, `SystemWakeCoordinator`, `ResourceMonitorService`, `ProcessResourceSampler`, `CodingAgentActivityReconciler`, and coding-agent hook installers under `Kaji/Services/CodingAgents/`. Built-in Codex, Claude Code, OpenCode, and Pi integrations emit into Kaji through `KajiHookClient` and `DistributedNotificationCenter`; native Kaji runtime emits directly through `KajiAgentActivityBridge` using its `KajiAgentScope.agentID` as the run identity and explicit parent-agent tab context from `NotificationNavigator`; provider hooks do not install shell notification scripts or interpreter one-liners. `ResourceMonitorService` resolves live Termy views through `TerminalViewRegistry` and samples the process tree rooted at the terminal child PID so foreground commands and their descendants are represented in top-bar and panel readings. `AIActivitySocketRouter` treats only root turn `start` and `stop` activity events as sidebar-running state, carries optional session and turn identifiers to ignore stale stops, and accepts `observe` events for tool, session, subagent, task, and transcript context without lighting the project activity border. `SystemWakeCoordinator` no longer wipes run history on sleep or wake; it restarts Codex/resource monitors and schedules `CodingAgentActivityReconciler` passes that mark interrupted live activities as stale when their pane or provider process does not recover after wake. Codex installs first-party `UserPromptSubmit` and root `Stop` activity hooks in `~/.codex/hooks.json`, observes `SessionStart`, tool, and subagent hooks without starting the border, and gets completion notifications from `CodexSessionMonitor` reading Codex session JSONL files in-process. Claude Code installs `UserPromptSubmit`, `Stop`, `Notification`, and `PermissionRequest` hooks in `~/.claude/settings.json`; OpenCode's plugin uses `session.status` or `tui.command.execute` to start, `session.status` idle/error or `session.idle` to stop, and does not start activity from message, todo, or tool events.
- Resource monitoring is app-lifetime rather than view-lifetime. Every five-second refresh captures one immutable Darwin process-table snapshot off the main actor, builds terminal root-plus-descendant trees from the same snapshot, deduplicates overlapping process identities per project, and keys CPU baselines by pane, PID, and process start identity. Foreground process groups affect display identity only; background agent workers remain included in totals. Refresh health and snapshot age are explicit, and wake reconciliation restarts the cadence without presenting stale measurements as current.
- Agent Mission Control: `AgentMissionControlPanel` is a sidebar footer popover that turns `AgentRunStore` and provider notifications into task-level rows. `AgentRunStore` is the source of truth for provider runs, preserving pane, provider, project, worktree, worktree path, confidence, lifecycle status, changed-file evidence, verification state, recent events, and bounded control-action records in `AgentRuns/index.json` summaries with per-run detail sidecars under `AgentRuns/Details` and changed-file chunks under `AgentRuns/ChangedFiles`; legacy `agent-runs.json` and v1 full-run indexes are migrated and compacted after the v2 summary index is valid; interrupted open runs reload as stale so restart never shows old work as actively running. `AgentRunMissionControlSnapshotBuilder` renders run-backed rows first and keeps provider notifications as fallback rows when no run exists for that pane. Live provider transcript snippets arrive through provider events and stay attached to both the legacy active activity and the new run model in memory. Completed runs capture a bounded git changed-file snapshot only when the worktree is not shared by another active run; overlapping runs in the same worktree are marked `shared worktree` so Kaji does not falsely attribute combined git changes to one agent. `AgentControlCenter` owns row action capabilities and execution for jump, reply, stop, new run, resume, verification, file open, and diff review so the SwiftUI views only render supported controls. `AgentMissionControlRow` keeps changed-file evidence collapsed by default, expands inline to show file paths, statuses, stats, attribution warnings, verification output, per-file open/diff actions, and a compact control tray. Reply and stop require a live exact-pane terminal; stop sends provider-specific Escape key events, with OpenCode receiving two Escapes and other providers receiving one; new run opens a fresh provider tab in the run worktree; resume is shown only when provider session metadata is available. Evidence actions first activate the run's project and worktree so files and diffs open in the right workspace. The initial verification runner detects Swift packages and executes `swift build && swift test` in the run worktree while storing the resulting status and trimmed output on the run. `AgentMissionControlNavigator` jumps from a row back to the owning pane or notification context.
- Settings and theming: `KajiConfig`, `ThemeService`, `AppTypographySettings`, `KeyBindingStore`, `CLILauncherSettings`, `KajiCLICommandInstaller`, `SleepPreventionController`, `IOKitSystemSleepAssertionManager`, `HugeIconCatalog`, `HugeIconFont`, and the views under `Kaji/Views/Settings/` and `Kaji/Views/Themes/`. Shared micro controls such as `KajiInput`, `KajiSelect`, `KajiSwitch`, and `KajiButtonStyle` live under `Kaji/Views/Components/` and use only `KajiTheme` tokens so form surfaces do not fall back to native control chrome. General Settings can install the `kaji` POSIX shell command into `~/.kaji/bin/kaji` and link it as `/usr/local/bin/kaji`; the command resolves the requested directory and opens Kaji through its URL command.
- Power controls keep idle and closed-lid behavior separate. `SleepPreventionController` owns one verified public IOKit `PreventUserIdleSystemSleep` assertion for automatic idle sleep only. `ClosedLidSessionController` owns bounded closed-lid sessions with duration, battery-floor, external-power, Low Power Mode, thermal-pressure, and heartbeat safety policies.
  Standard mode is explicitly experimental until the current hardware model and exact macOS build pass the guided physical continuity test. A Kaji-owned `KajiClosedLidGuard` process owns private IOPM root-domain selector 12 through bounded JSONL IPC, watches the parent PID and heartbeat, and restores normal clamshell behavior on timeout, EOF, signal, parent death, shutdown, or normal exit; Kaji independently restores if the guard dies.
  Power Protect is optional and direct-distribution only. A signed `SMAppService` LaunchDaemon accepts only Kaji clients matching its code-signing requirement, exposes a fixed XPC interface, and executes only `/usr/bin/pmset -a disablesleep 0|1` plus read-only `pmset -g`. It verifies `SleepDisabled` after every mutation, restores on startup and unregister, and uses a short watchdog to restore after heartbeat loss. Normal quit is deferred until live restoration succeeds. The UI discloses that Power Protect disables every automatic sleep path while active and requires explicit helper approval.
- Updates: `UpdateService` integrates Sparkle for macOS app updates.

## Persistence

Kaji stores app data under `~/Library/Application Support/Kaji/`.

- `projects.json`: tracked projects. `sortOrder` is normalized to a contiguous `0..<count` sequence on every load, add, and remove so gaps or duplicates from past removals cannot persist.
- `project-removal-tombstones.json`: `ProjectRemovalService` recovery state. Each tombstone carries `project`, `worktrees`, `cleanupOnDisk`, and a backward-compatible `retryCount` (missing keys decode as zero). Failed recovery attempts increment `retryCount`; after `ProjectRemovalService.maxRetryCount` consecutive recovery failures the file is physically moved aside to `project-removal-tombstones.json.stale-<yyyyMMdd-HHmmss>` so a permanent failure can never block app launch.
- `worktrees/*.json`: per-project worktree metadata
- workspace persistence files: tabs, splits, and selection state
- notification persistence files used by `NotificationStore`
- `notification-integrations.json`: outbound notification destinations and routing rules
- `AgentRuns/index.json` plus `AgentRuns/Details/` and `AgentRuns/ChangedFiles/`: recent Agent Mission Control summaries, per-run event/action/verification details, bounded changed-file previews, and chunked changed-file evidence. Legacy `agent-runs.json` and v1 full-run indexes are migration sources and are compacted after a valid v2 summary index exists
- `parent-agent-tasks.json`: Parent Agent threads, timelines, child-run links, and stale restored tasks
- `speech-input-settings.json`: selected speech model, hold hotkey, enablement, warm-model preference, and insertion behavior
- `speech-models.json`: editable Speech to Text model registry copied from the bundled defaults on first use
- `meeting-notes-settings.json`: v4 source selection, separate notes destination, endpoint profile and immutable endpoint snapshot, dynamically discovered or manually entered transcription model metadata, exact STT provider/model/mode/region/retention route, endpoint-bound credential profile reference, account-control attestations with exact claims, languages, diarization, bounded keyterms and provider-safe options, context scope, and bounded style instructions. Version-3 and older documents migrate onto the matching built-in endpoint profile; fresh consent uses the version-4 destination disclosure.
- `meeting-stt-endpoints.json`: 0600 custom transcription endpoint profiles merged with immutable bundled presets from `meeting-transcription-endpoints.json`. Profiles contain no secrets and define the provider protocol variant, normalized HTTPS/WSS base URLs, model discovery method, and stable region identity.
- `meeting-stt-model-catalogs.json`: 0600 bounded last-known-good model discovery results keyed by endpoint profile and credential profile. The cache stores model IDs and non-secret provider metadata only, preserves unavailable selected models, and is never shared across endpoints or accounts.
- `meeting-stt-credential-profiles.json`: 0600 non-secret STT credential profile metadata under a repaired 0700 parent; each profile is bound to one endpoint profile and exact origin fingerprint. Symlinks are rejected, profile-label plaintext is disclosed, and secret values exist only in the non-synchronizing data-protection Keychain with `WhenUnlockedThisDeviceOnly`.
- `Meetings/index.json` and `Meetings/Sessions/`: 0600 versioned AES-GCM envelopes under 0700 directories. A per-installation 256-bit key lives in the non-synchronizing data-protection Keychain, sidecar authenticated data binds the session ID and envelope version, and the separately authenticated encrypted index hides titles, project IDs, lifecycle, and pin state. Valid plaintext documents migrate only after successful decode and validation. Missing or incorrect keys fail generically without overwriting ciphertext. Documents contain committed final transcript metadata, note revisions, synthesis cursor, frozen endpoint/model consent configuration and claims, and sanitized audio/transcription gaps. Deletion tombstones and retention cleanup remain restart-safe. Production capture keeps raw audio in bounded memory and never persists it.
- `ai-gateway-settings.json`, `ai-gateway-secrets.json`, and `ai-gateway/claude-code-router/`: local AI Gateway settings, file-permission-protected gateway/provider secrets, and the Claude Code Router install/config/runtime directories
- `FluidAudio/Models/`: cached FluidAudio speech model files downloaded by the Speech to Text settings pane
- `termy.conf`: Kaji-managed Termy config snapshot with theme colors, app-owned terminal typography, terminal behavior settings, shell integration, and active/inactive line-based scrollback caps for large-output sessions
- Termy-format theme files imported, exported, and user-created by `ThemeService`
- `cli-launchers.json`: enabled CLI footer launchers and their commands
- Kaset Music stores only Kaji-owned feature flags and panel width in `UserDefaults`; Kaset owns its own YouTube/Google session storage through the package implementation

The source repo may also contain `.kaji/worktree.json` files inside user projects. Those files define setup commands for newly created worktrees.

## Termy Integration

`scripts/setup.sh` builds `libtermy_ffi.dylib` from pinned upstream `lassejlv/termy`, applies Kaji's FFI patch for child PID, config color reload, and scrollback selection text, installs `TermyKit/termy.h`, syncs Termy shell assets into `Kaji/Resources/termy/shell`, and installs the patched bundled Rift CLI under `Kaji/Resources/Rift`.

The app only talks to libtermy through the C ABI exposed by `TermyKit/termy.h`. Swift terminal code lives under `Kaji/Services/Termy/` and `Kaji/Views/Terminal/Termy/` so libtermy concerns stay isolated from workspace and coding-agent logic.
